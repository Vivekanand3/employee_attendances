# Starter review

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | It rounds elapsed seconds down before testing the 10-minute grace period; 09:40:01 is therefore treated as on time. It also assumes the shift starts on the same calendar day. | Check 09:40:00 versus 09:40:01 for a 09:30 shift, and punch in during the early hours of an overnight shift. | Truncate instants to seconds, compare elapsed seconds strictly to 600, and anchor overnight shift starts correctly. |
| 2 | `compute_work_hours` | Built-in `round` uses half-even rounding, not the contract's half-up rule. | Exercise a duration whose hour value is exactly halfway at two decimal places. | Round using `Decimal` and `ROUND_HALF_UP`. |
| 3 | `compute_overtime` | It counts any overtime minute rather than requiring at least 30 minutes, and it does not move an overnight shift end to the next day. | Check 29 versus 30 minutes after shift end and an overnight shift. | Anchor shift end to the proper shift day and apply the 30-minute threshold. |
| 4 | `create_employee` | Checking for a duplicate before inserting is race-prone; concurrent requests can both pass. It also returns a naive timestamp instead of epoch milliseconds. | Send parallel creates with the same `emp_code`; inspect `created_at` in the response. | Enforce uniqueness with a MongoDB index, translate duplicate-key errors to 409, and serialize timestamps as epoch milliseconds. |
| 5 | `EmployeeIn` | The starter accepts malformed employee codes, emails, dates, shifts, and equal shift start/end values. | Submit values outside the schemas in `openapi.yaml`. | Add request validation for required formats, bounds, and shift duration. |
| 6 | `list_employees` | `page * page_size` skips the first page; `total` ignores the department filter; results have no required sort or pagination bounds. | Request page 1 and compare filtered totals/order. | Use `(page - 1) * page_size`, count the filtered query, sort by code, and constrain paging inputs. |
| 7 | `punch_in` | An unknown employee causes a `None` lookup result to be indexed; timestamp conversion uses the host's local timezone; `punched_at=0` silently becomes “now”. | Punch an unknown code, run in a non-UTC timezone, or submit zero. | Return 404 for unknown employees, parse explicit IST times, and validate input instead of using truthiness. |
| 8 | `punch_in` | Check-then-insert permits duplicate attendance records under concurrency. It also omitted the overnight attendance-date rule and whole-second truncation. | Send simultaneous punches or punch an overnight shift before its shift-end time. | Add a unique (`emp_code`, `date`) index and derive/store the normalized attendance date and instant. |
| 9 | `punch_in` | The starter does not constrain presence statuses or guarantee epoch-millisecond response fields. | Send `ABSENT`, an unknown status, or inspect the response timestamps. | Restrict statuses to the three punchable values and serialize instants at the API boundary. |
| 10 | `list_attendance` | It loads the entire collection and sorts/pages in Python, which does not scale; equal-date ordering is unspecified. | Run against a large collection and compare stable ordering across pages. | Apply filters, sort, count, skip, and limit in MongoDB with supporting indexes. |
| 11 | `list_attendance` | It leaks MongoDB `_id` as an API `id` and returns BSON datetimes rather than the contract's epoch milliseconds. | Inspect response fields for `_id`/`id` and timestamps. | Serialize only contract fields and convert timestamps to epoch milliseconds. |
| 12 | `list_attendance` | Page values were not bounded, and reversed date ranges were not rejected. | Request page 0, page size 101, or `date_from` after `date_to`. | Add query validation and return 422 for an invalid date range. |
| 13 | API routes | Health always reported success without checking MongoDB, while several required endpoints did not exist. | Stop MongoDB or request the missing routes. | Ping MongoDB for readiness and implement the contracted punch-out, regularization, analytics, and explain routes. |
| 14 | API response boundaries | Seeded documents may omit `history` or `half_day`; directly returning database documents can also leak internal fields. | Read a seeded record missing those optional fields. | Supply documented defaults and explicitly serialize employee, attendance, history, and explain responses. |

`compute_late_minutes` returning zero for a punch at or before the grace boundary is intentional; the defect was its
minute-level comparison, which lost the seconds needed to distinguish 09:40:00 from 09:40:01.
